# Localization and language handoff verification

On 23 August 2026, the live Vercel website was checked after the localization update. Selecting **Simplified Chinese** immediately changed the homepage navigation, headline, explanatory sections, extension section, support section, language controls, and the entire setup flow into Chinese. The saved language control visibly confirmed the selection.

The localization provider writes the chosen site language to `under-progress-language` and sends the same normalized value in the trusted `under-progress-website` `set-language` message. The website regression suite verifies that a Chinese selection produces `zh-CN` and an Arabic browser hint produces `ar` for that message. The extension bridge regression suite verifies that the content script receives `set-language`, persists the language in `underProgressSpeechLanguage`, and applies the matching selected voice for Read Aloud.

The published Vercel deployment for commit `c7a427b` completed successfully. A clean Chromium run loaded the published v0.5.5 extension, selected Simplified Chinese in the live website language control, observed the Chinese headline, and verified that the extension stored `underProgressSpeechLanguage` and `underProgressProfile.language` as `zh-CN`.

The later v0.5.7 extension release adds **optional free translation before speech**. When the user enables the popup’s **Translate before speaking** control, the popup first shows **“Translating selected text for your saved language…”**. Only the short selected text requested for Read Aloud, capped at 430 characters, is sent to MyMemory for translation into the saved speech language. The extension then speaks that translated text with the matching installed voice. The control remains off by default; when it is off, Under Progress refuses cross-language speech instead of reading English through a mismatched language voice.

The final regression suite verified three boundaries: the MyMemory request returned Chinese text from the extension service worker; on a normal English page with an available Chinese voice, the translated Chinese string—not the English source—was the string passed to speech; and the released stable v0.5.7 package still refuses a silent browser-default fallback where no matching Chinese voice exists.

The language selector was subsequently restored to its full 37-language list, including Arabic variants, Amharic, Bangla, Persian, French, German, Greek, Gujarati, Hebrew, Hindi, Indonesian, Italian, Japanese, Korean, Malayalam, Marathi, Nepali, Polish, Portuguese, Punjabi, Romanian, Russian, Somali, Spanish, Swahili, Tamil, Telugu, Thai, Turkish, Ukrainian, Urdu, Vietnamese, and Filipino. A live Vercel verification selected Filipino and confirmed it was saved as the exact `tl-PH` preference for extension translation and Read Aloud. Full website text remains available in English, Arabic, Simplified Chinese, and Traditional Chinese; the other available language choices remain available for free selected-text translation and matching-voice Read Aloud.

The full live website-to-extension test then loaded the published v0.5.7 package, selected Filipino (`tl-PH`) on the Vercel website, and confirmed that both `underProgressSpeechLanguage` and the extension profile retained the exact `tl-PH` locale. The Read Aloud reply carried `tl-PH` and requested a matching Filipino voice rather than silently selecting a default browser voice.
