# Live full-interface translation verification

On 23 August 2026, the deployed Vercel website was opened with Filipino (`tl-PH`) selected. The language dialog showed the restored global language list and the explicit progress state **“Translating the full website interface…”**. The free translation process advanced from 20 of 156 interface messages through 41, 75, and 92 messages during the live check, confirming that the selected language initiates whole-interface translation rather than only changing the speech voice. The selected locale continues to be stored for the extension Read Aloud handoff.

After the protected-term repair was deployed, the cache revision changed and the Filipino translation correctly restarted from a fresh cache, visibly progressing from 19 through 47, 63, 96, 111, and 150 of 156 messages. An earlier run completed and showed Filipino text across the page while keeping **Under Progress**, **SAS**, and **Read Aloud** intact rather than displaying normalized placeholder markers. The later explicit-English-source production check reached the free provider limit before completion; no claim is made that this last post-fix Filipino check completed.

The final deployed build was also checked with Urdu (`ur-PK`). Selecting Urdu immediately persisted `ur-PK`, applied `dir="rtl"`, mirrored the interface layout, and started the same full-interface translation workflow, confirming that the right-to-left language path uses the selected locale rather than falling back to English.

The final deployment was verified with the bundled Persian (`fa-IR`) language pack. It immediately switched the title, navigation, hero, journey, extension section, language dialog, and support section into Persian with a right-to-left layout, while preserving product and technical identifiers such as **Under Progress**, **SAS**, **Chrome**, **Edge**, and **Read Aloud**. The language dialog now names the **selected** language rather than the browser hint.

The site uses a hybrid strictly no-cost model: 19 full interface packs are bundled for immediate switching, including Persian, French, German, Greek, Hebrew, Hindi, Indonesian, Italian, Japanese, Korean, Malayalam, Marathi, Nepali, Polish, Portuguese, Punjabi, Romanian, Russian, and Spanish. The other restored global selections use a free cached translation workflow with a visible 156-message progress indicator. The provider may pause when its free request limit is reached, so the website now saves each completed message and intentionally retries only the missing messages when the same language is selected again. It does not switch to a paid or user-pays service. In every case, the exact selected locale is saved and posted to the extension. The final live website-to-extension regression against the published v0.5.7 extension package passed after the full-interface change, confirming the selected locale is retained for Read Aloud.

After the explicit English-source refinement, a fresh Filipino (`tl-PH`) run began from the final deployed page and displayed the 156-message progress state. Separately, the final live localized-language regression opened the production website with the published extension, selected Chinese (`zh-CN`), and sent an actual `speak` request through the extension. The reply retained `zh-CN` and correctly refused browser-default fallback because the headless environment has no matching Chinese voice.

The subsequent strict no-cost update was deployed successfully to Vercel. Its live Filipino dialog explicitly distinguishes built-in full-interface packs from the free service fallback and explains that an interrupted translation can continue from saved progress. On load, the live fallback reported progress at 16 of 156 messages and then advanced through 52 and 71 of 156 before the provider paused. The live dialog showed the new recovery message, retained the saved Filipino locale for Read Aloud, and accepted a same-language retry without changing the locale or reverting to browser-default speech. This confirms the consent and locale-preservation behavior; the persisted cache count is inspected separately before claiming a successful later continuation.
